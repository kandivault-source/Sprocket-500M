Step 1 · The Tokenizer

A model can't read letters — only numbers. The tokenizer is the translator: it chops text into common chunks ("tokens") and gives each one a number. We built ours from scratch by showing it 200 million words and letting it discover the ~32,000 most useful chunks. Type anything below and watch it split in real time.

Byte-level BPE, 32,000 vocab, trained from scratch on 200M tokens of FineWeb-Edu. 8 special tokens reserved at ids 0–7 for the chat/tool protocol. Compression ≈ 4.52 chars/token. Live encode below hits the real tokenizer via /api/tokenize.

What Fits On The Card

Training needs far more memory than the finished model — it has to remember how to improve every single number. Here's how much each size needs versus the ~7 GB the 4060 actually has free.

Training footprint ≈ 16 bytes/param (fp32 weights + grads + AdamW moments). The 4060 has ~7 GB usable after the desktop. Above the line = won't train locally.

Anything past the red line has to train on a rented cloud GPU — its memory won't fit here.
Local training ceiling ≈ 340M params. The 1B needs 17.7 GB of optimizer state → cloud-only. CPU-RAM offload can lift the memory wall, but not the 4060's compute wall.

Speed & The Memory Cliff

More examples at once = faster training… until it overflows the card and falls off a cliff, running ~9× slower. We stay just left of the cliff.

125M model, 1024-token sequences, bf16. Micro-batch 4 is the sweet spot (5.5 GB, 18.1k tok/s). Batch 6+ spills to shared memory and collapses.

How Far It Can See

The "context" is how much text the model can hold in mind at once. Bigger sounds better, but the memory it needs grows fast — here's what a 1B model would need to remember a given amount, and where it stops fitting.

KV-cache at inference for the 1B config (22 layers, 8 KV-heads, head_dim 128) = 88 KB/token. Full attention — no windowing. Reaching long context = pretrain short then extend via RoPE scaling.

KV-cache memory needed 4060 limit (~7 GB) cloud A100 limit (80 GB)
Your target of true 64k context fits comfortably. A full million tokens would need 90 GB just to remember — more than even a big cloud GPU — so we aim high but realistic.
64k full-attention = 5.6 GB cache (cloud-easy). 128k = 11.5 GB (exceeds the 4060 for inference). 1M = 90 GB (exceeds an 80 GB A100). Attention compute is O(T²): 1M ≈ 15,000× an 8k pass.
